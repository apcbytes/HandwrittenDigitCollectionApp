✦The core tension

Language is for people. Math is for machines. NLP is the bridge.

A model only ever does arithmetic on numbers. Human language, though, is ambiguous, noisy, and endlessly varied. Almost everything in this page exists to close that gap — to convert words into numbers without throwing away the meaning.

Ambiguity

“book a flight” (verb) vs “read a book” (noun). Same letters, different meaning — context decides.

Noise

Real text is full of URLs, @mentions, emojis, typos, ALL CAPS and creative punctuation!!! Some of it is junk; some of it is signal.

Variety

“late”, “delayed”, “held up”, “stuck on the tarmac” all mean the same thing to a person and look totally different to a computer.

The mental model that never changes: clean → tokenize → normalize → vectorize → model → evaluate. Modern transformers fold the first four steps into a learned layer, but understanding the classic line is the fastest way to understand the modern one. So let's walk it.

01Clean · Tokenize · Normalize Beginner

The Text Refinery

Type any tweet-like sentence, then step through the pipeline and watch the exact transformation happen to your words. This is stages 1–3 of the line, made tangible.

1 · Cleaning & normalization

Lowercase everything so Flight, flight and FLIGHT count as one word. Strip URLs and @mentions, drop the # off hashtags (keeping the word), and remove stray punctuation and digits. Then collapse repeated whitespace.

Watch out: cleaning is lossy and task-specific. For sentiment, !!! and 😤 are signal, not noise. For topic detection they are noise. Always ask: does this token help my task?

2 · Tokenization

Split text into units — usually words. It looks trivial (text.split()) but is subtle: how do you treat don't, U.S.A., or state-of-the-art? Regex like \w+ is a solid start; libraries such as NLTK/spaCy handle the edge cases.

Subwords are the modern default: transformers break rare words into reusable pieces (tokenization → token + ##ization), giving a small fixed vocabulary that can spell out any word — even typos — with no “unknown word” problem.

3a · Stopword removal

Stopwords are ultra-common, low-information words: the, is, a, to, and. Removing them shrinks the feature space and cuts noise for search, topic modeling and bag-of-words classifiers.

Watch out: for sentiment and deep models, stopwords can matter — not good ≠ good. Removal is a knob you tune, not a law.

3b · Stemming vs. lemmatization

Both fold word variants to a base form so flies / flying / flew count together.

  • Stemming — fast, crude suffix chopping. May produce non-words: studies → studi, and can over-cut: caring → car.
  • Lemmatization — dictionary + part-of-speech aware, always returns a real word: studies → study, better → good. Slower but cleaner.

Rule of thumb: stem for speed when readability doesn't matter; lemmatize when correctness does.

In our airline project: we lowercase, strip URLs/mentions, keep letters only, and let TF-IDF drop stopwords — a deliberately light clean, because emotive words are exactly what predicts sentiment.
04Represent text as numbers Beginner → Intermediate

Bag-of-Words: from tokens to a matrix

Models need numbers. The simplest recipe: count how often each vocabulary word appears in each document. Order is thrown away — hence “bag”. Press play and watch the matrix fill in.

Each row is a document, each column a vocabulary word, each cell a count. Notice how many cells stay zero — real vocabularies have tens of thousands of columns, so NLP stores these as sparse matrices (only the non-zeros), never as dense grids.

Why it works — and where it breaks

Bag-of-Words is a shockingly strong baseline: with a linear classifier on top it still competes on many tasks. But by discarding order it can't tell not good from good not, and it treats good and great as totally unrelated columns.

N-grams put some order back

An n-gram is a run of n consecutive tokens. Adding bigrams gives the model short phrases as features — not good, on time, customer service — which often buys a real accuracy jump for a tiny cost.

05Weighting words by importance Intermediate

TF-IDF: quiet down the common, amplify the distinctive

Raw counts overweight boring words like the. TF-IDF multiplies how often a word appears in a document (term frequency) by how rare it is across all documents (inverse document frequency). The bars below compare a plain count with its TF-IDF weight.

Word
Raw count
TF-IDF weight

Words in every document (like the, was) get crushed toward zero — they can't distinguish anything. Distinctive words (delayed, crew) rise to the top. That is exactly the signal a classifier wants.

The formula, in plain terms

tfidf(t, d) = tf(t, d) × log( N / (1 + df(t)) )

tf(t,d) = how often term t appears in document d · N = number of documents · df(t) = how many documents contain t. High local frequency × high global rarity = high weight.

Then: cosine similarity

Once every document is a vector, “how similar are two documents?” becomes “how small is the angle between their vectors?” Cosine similarity returns 1 for identical direction, 0 for unrelated — and ignores length, so a long and a short review on the same topic still match. This is the seed of semantic search and recommendation.

06Dense embeddings Advanced

Teaching words their meaning

TF-IDF vectors are huge, sparse, and “orthogonal” — good and great share no dimensions. Embeddings fix this: each word becomes a short, dense vector learned so that words used in similar contexts land near each other. Watch scattered words drift into meaning-based clusters.

complaint words praise words question words neutral / logistics

Static vs. contextual

Static embeddings (word2vec, GloVe) give one fixed vector per word — enough for the famous analogy king − man + woman ≈ queen. Contextual embeddings (BERT, GPT) compute a fresh vector each time, so bank differs in “river bank” vs “bank account”.

You can get dense vectors with zero downloads

LSA (Latent Semantic Analysis) runs TF-IDF then compresses it with truncated SVD to a handful of dimensions — a quick, dependency-free way to place documents in a semantic space and even plot them, exactly like the galaxy above.

✦Linguistic structure Intermediate

Sometimes you want the grammar back

Bag-of-Words discards structure. Two tools recover it: part-of-speech tagging labels each word's grammatical role, and named-entity recognition pulls out real-world things. Hover the sentence to see both.

PROPN / NOUN VERB entity (ORG / GPE / DATE)

POS tagging disambiguates book a flight (verb) from read a book (noun). NER turns free text into structured records: United → ORG, Denver → GPE, Monday → DATE — the backbone of information extraction and question answering.

07Machine learning on text Intermediate

Train a classifier — then judge it honestly

Supervised learning chains the whole line: clean → tokenize → vectorize → feed a model labelled examples → let it predict new text. The hard part isn't training; it's measuring quality without fooling yourself.

Three classic, reliable models

  • Multinomial Naïve Bayes — lightning fast, a great first baseline for word counts.
  • Logistic Regression — linear, well-calibrated, and interpretable: each word's coefficient is its vote for a class.
  • Linear SVM — often the strongest classic linear text classifier.
One habit that saves you: wrap the vectorizer + model in a single pipeline. It guarantees the identical transform is applied to train and test — preventing data leakage, the silent bug that inflates scores.

Why accuracy alone lies

If 95% of tweets are negative, a model that always shouts “negative” is 95% accurate and completely useless. Use metrics that survive imbalance:

  • Precision — of what I labelled class X, how much was right? (punishes false alarms)
  • Recall — of what truly is class X, how much did I catch? (punishes misses)
  • F1 — the harmonic mean of the two; macro-F1 weights every class equally.
  • Confusion matrix — the full predicted-vs-actual grid that shows which classes get mixed up.

09The modern frontier Advanced

Attention: every word looks at every other word

Transformers (BERT, GPT) power today's state of the art. The key idea is self-attention: to understand one word, the model weighs how much every other word matters to it — computing meaning in full context. Hover a word to see where it “looks”.

Hover it — attention flows back to flight, resolving what “it” refers to. That contextual resolution is why transformers give a different vector to the same word in different sentences, and why they beat bag-of-words on nuance, sarcasm, and long-range meaning.

The through-line: transformers didn't discard the refinery — they learned stages 1–4 (a subword tokenizer plus embeddings) and made the “vectorize” step context-aware. Everything you walked through above is still happening, just inside the network.

01

Cleaning & Normalization

Beginner▶
🔍Intuition

A tweet like “@Delta my FLIGHT is delayed 3hrs!!! 😤” is mostly packaging. The signal is flight delayed. Cleaning makes identical meanings look identical: Flight, flight, FLIGHT should be one token, not three.

📐Math
c: raw → normalized   (deterministic). Effect: lowercasing alone can shrink the vocabulary |V| by 30–50% on social text, directly lowering model variance.
🧩Concept

Ordered steps: lowercase → remove URLs/mentions → keep-or-strip emoji & punctuation → unicode-normalize → collapse whitespace. It is lossy and task-specific — for sentiment, !!! and 😤 are signal.

💻Code demo
import re
def clean_text(t, keep_emoji=False):
    t = t.lower()
    t = re.sub(r"http\S+|www\.\S+", " ", t)   # URLs
    t = re.sub(r"@\w+", " ", t)                 # mentions
    t = re.sub(r"#(\w+)", r"\1", t)            # keep hashtag word
    if not keep_emoji:
        t = re.sub(r"[^a-z\s]", " ", t)         # letters only
    return re.sub(r"\s+", " ", t).strip()

clean_text("@Delta my FLIGHT is delayed 3hrs!!! 😤 http://t.co/x")
# -> 'my flight is delayed hrs worst'
✅Key takeaways
  • Cleaning shrinks vocabulary & noise but discards information — choose per task.
  • Keep a raw copy; never clean in place.
  • For sentiment prefer a light clean (emojis/! carry mood).
🎤Interview Q&A
Why lowercase, and when is it harmful?
It merges casing variants to cut sparsity. Harmful when case is signal: NER (Apple vs apple), acronyms (US vs us), and ALL-CAPS shouting for sentiment. Keep a case feature or skip lowercasing there.
Should you remove emojis and punctuation?
Task-dependent. Topic models: yes. Sentiment/emotion: emojis and repeated punctuation are strong features — keep them or engineer counts like num_exclamations.
What is Unicode NFKC normalization?
The same glyph can have several byte forms (é as one codepoint vs e + combining accent). NFKC canonicalizes them so matching and tokenization behave consistently.
02

Tokenization (word → subword / BPE)

Beginner▶
🔍Intuition

To count or embed words you must define what a word is. “state-of-the-art” — one token or four? “don't” — do + n't? These choices change every downstream number.

📐Math
tok: text → (v1,…,vk),   vi ∈ {0,…,|V|-1}.   BPE learns V by greedily merging the most frequent adjacent symbol pair, repeated m times → no out-of-vocabulary tokens.
🧩Concept

Three granularities: word (simple, big vocab, OOV problem), subword (BPE/WordPiece/SentencePiece — the transformer default), character (tiny vocab, long sequences).

💻Code demo
# A tiny Byte-Pair Encoding learner (the idea behind GPT/BERT tokenizers)
from collections import Counter
import re
def learn_bpe(words, num_merges=8):
    vocab = {" ".join(list(w))+" </w>": c for w,c in Counter(words).items()}
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for w,f in vocab.items():
            s = w.split()
            for i in range(len(s)-1): pairs[(s[i],s[i+1])] += f
        if not pairs: break
        best = pairs.most_common(1)[0][0]; merges.append(best)
        pat = re.compile(r"(?<!\S)"+re.escape(" ".join(best))+r"(?!\S)")
        vocab = {pat.sub("".join(best), w): c for w,c in vocab.items()}
    return merges

learn_bpe("low lower lowest newer newest new".split())
# -> [('e','r'), ('er','</w>'), ('n','e'), ('ne','w'), ...]
✅Key takeaways
  • Word tokenization suffers OOV and huge vocabularies.
  • Subword (BPE) is the modern default: fixed vocab, no OOV, reusable pieces.
  • Tokenization is a modeling decision, not trivia.
🎤Interview Q&A
Why do transformers use subword tokenization?
To bound the embedding table size while representing any word (typos, rare, new) with no <UNK>. Rare words split into frequent subwords, sharing statistical strength: unhappiness → un + happi + ness.
How does BPE build its vocabulary?
Start from characters; repeatedly merge the most frequent adjacent symbol pair; stop after a fixed number of merges. The merge list is the tokenizer.
Character vs word trade-off?
Char: tiny vocab, no OOV, but long sequences and weak per-token features. Word: short sequences, strong features, but huge vocab and OOV. Subword sits between and usually wins.
03

Stopwords, Stemming & Lemmatization

Beginner▶
🔍Intuition

the, is, a are everywhere and rarely change meaning — dropping them focuses the model. And delayed / delay / delays are one idea; folding them to delay concentrates signal instead of scattering it over three columns.

📐Math
Stopword removal ≈ feature selection: drop terms with I(term; label) ≈ 0.   Stem/lemma reduce |V| by mapping surface forms → one lemma, lowering sparsity and estimator variance.
🧩Concept

Stemming = crude suffix chopping (Porter): fast, may make non-words (studies→studi). Lemmatization = dictionary + POS aware: real words (better→good), slower, cleaner.

💻Code demo
from sklearn.feature_extraction.text import ENGLISH_STOP_WORDS as STOP
def porter_lite(w):
    for suf in ("ingly","edly","ing","ed","ly","es","s"):
        if w.endswith(suf) and len(w)-len(suf) >= 3: return w[:-len(suf)]
    return w

sent = "the crew was flying and the delays were cancelling everything"
kept = [w for w in sent.split() if w not in STOP]
[porter_lite(w) for w in kept]
# -> ['crew', 'fly', 'delay', 'cancel', 'everyth']
✅Key takeaways
  • Stopword removal helps BoW/topics; can hurt sentiment (not good).
  • Stem for speed, lemmatize for correctness.
  • Both shrink |V| and curb overfitting on small data.
🎤Interview Q&A
Stemming vs lemmatization — when which?
Stemming for speed at scale (search indexing). Lemmatization when correctness/interpretability matters. On deep models, often neither — subword + embeddings handle morphology.
A case where removing stopwords hurts?
Negation/sentiment: dropping not/no/never flips meaning (not good → good). Also phrase search and MT.
Why can stemming reduce accuracy?
Over-stemming merges unrelated words (university/universe → univers); under-stemming leaves variants split. Validate empirically.
04

Bag-of-Words & N-grams

Beginner → Intermediate▶
🔍Intuition

Give each unique word a column; each document becomes a row of counts. “good movie” and “movie good” get the same vector — order is gone. N-grams glue neighbors so not good survives.

📐Math
d → x ∈ ℝ|V|, xi = count(termi in d).   Matrix X ∈ ℝN×|V| is very sparse → store non-zeros (CSR). An n-gram is a contiguous tuple (wj,…,wj+n-1).
🧩Concept

BoW + a linear model = strong, fast baseline. Blind spots: order (beyond n-grams) and semantics (good≠great).

💻Code demo
from sklearn.feature_extraction.text import CountVectorizer
corpus = ["the flight was delayed","great crew great service","not good service"]
cv = CountVectorizer(ngram_range=(1,2))      # unigrams + bigrams
X = cv.fit_transform(corpus)
print(cv.get_feature_names_out())            # includes 'not good', 'great crew'
print(X.toarray())                            # sparse counts
print("sparsity: %.0f%% zeros" % (100*(1 - X.nnz/(X.shape[0]*X.shape[1]))))
✅Key takeaways
  • BoW is sparse, order-blind, semantics-blind — yet a great baseline.
  • Bigrams cheaply recover local order (not good, on time).
  • Always store sparse.
🎤Interview Q&A
Why store BoW sparsely?
A doc uses a tiny fraction of |V|, so >99% of cells are zero. Dense N×|V| is infeasible (1M×50k). CSR stores only non-zeros, cutting memory orders of magnitude.
Downsides of higher-order n-grams?
Feature explosion → sparsity, memory, overfitting, diminishing returns. Cap at bi/trigrams; prune with min_df.
How does BoW handle unseen test words?
They're dropped (no column). Hence fit the vectorizer on train only, inside a pipeline; subword models are more robust.
05

TF-IDF & Cosine Similarity

Intermediate▶
🔍Intuition

Counts overweight boring words. the is constant but distinguishes nothing; refund is rare and telling. TF-IDF boosts rare-but-local words and mutes ubiquitous ones.

📐Math
tfidf(t,d) = tf(t,d) × 1+N1+df(t) log (+1)   then L2-normalize rows.
cos(a,b) = a · b‖a‖ ‖b‖ ∈ [0,1]  (non-negative tf-idf)
🧩Concept

TF-IDF is BoW re-weighted — the workhorse representation for classical text ML and pre-embedding semantic search.

💻Code demo
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
docs = ["the flight was delayed and the service was bad",
        "bad delayed flight terrible service",
        "the crew was friendly and the flight was great"]
Xt = TfidfVectorizer().fit_transform(docs)
print(cosine_similarity(Xt).round(2))
# doc0 & doc1 (both complaints) score high; doc2 (praise) lower
✅Key takeaways
  • TF-IDF = term freq × inverse doc freq; distinctive words win.
  • L2-normalize, then cosine compares direction, ignoring length.
  • Cosine underlies search, dedup, recommendation.
🎤Interview Q&A
Why does IDF use a logarithm?
Doc frequencies span orders of magnitude; log compresses that range and encodes diminishing information — rare→somewhat-rare matters more than common→very-common.
Why cosine, not Euclidean, for text?
Text vectors vary wildly in magnitude (length). Cosine is scale-invariant and measures topic orientation, so short and long docs on one topic match.
What limitation do embeddings fix?
TF-IDF has no meaning: good and great are orthogonal (zero similarity). Embeddings place synonyms near each other.
06

Word & Document Embeddings

Advanced▶
🔍Intuition

Give every word a short vector so words used in similar contexts sit close. Then king − man + woman ≈ queen becomes literal vector arithmetic. Meaning becomes geometry.

📐Math
skip-gram: maximize Σ log p(wt+j | wt),   p(o|c) = exp(uo·vc)Σw exp(uw·vc)  (neg-sampling avoids the giant sum).
LSA: factorize X ≈ U Σ VT (truncated SVD) → top-k directions = latent topics.
🧩Concept

Static (word2vec/GloVe/fastText): one vector per word. Contextual (BERT): vector depends on the sentence. LSA: dense vectors with only scikit-learn.

💻Code demo
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.decomposition import TruncatedSVD
docs = ["flight delayed lost luggage terrible","cancelled flight rude staff no refund",
        "friendly crew great flight landed early","comfortable seats lovely crew wonderful"]
emb = TruncatedSVD(2, random_state=0).fit_transform(
        TfidfVectorizer(stop_words="english").fit_transform(docs))
emb.round(2)   # 2-D dense vector per document -> complaints vs praise separate
✅Key takeaways
  • Embeddings = dense vectors where distance ≈ similarity of meaning.
  • word2vec learns from context; LSA factorizes the term-doc matrix.
  • Contextual embeddings give a different vector per sentence.
🎤Interview Q&A
word2vec vs GloVe?
word2vec is predictive (local windows, shallow net). GloVe factorizes the global co-occurrence matrix so dot products ≈ log co-occurrence. Similar vectors, different training.
Why do static embeddings fail on polysemy?
One vector must average all senses of bank. Contextual models (BERT) compute the vector from the whole sentence, giving sense-specific representations.
How does fastText handle OOV?
It embeds character n-grams and sums them, so unseen words still get a vector — great for typos and morphologically rich languages.
07

POS Tagging & NER

Intermediate▶
🔍Intuition

book is a verb in “book a flight”, a noun in “read a book”. POS tags the role; NER pulls entities (United→ORG, Denver→GPE) — turning free text into structured records.

📐Math
Linear-chain CRF scores a whole tag sequence: score(x,y) = Σt [ ψemit(xt,yt) + ψtrans(yt-1,yt) ], normalized by the forward algorithm.
🧩Concept

Both are sequence labeling — neighbors matter. Modern taggers: BiLSTM-CRF or transformers; spaCy wraps it in one call.

💻Code demo
import spacy
nlp = spacy.load("en_core_web_sm")         # pip install spacy; python -m spacy download en_core_web_sm
doc = nlp("United Airlines delayed my flight from Boston to Denver on Monday.")
print([(t.text, t.pos_) for t in doc][:5])
print([(e.text, e.label_) for e in doc.ents])
# [('United','PROPN'),('Airlines','PROPN'),('delayed','VERB'),...]
# [('United Airlines','ORG'),('Boston','GPE'),('Denver','GPE'),('Monday','DATE')]
✅Key takeaways
  • POS = grammatical role; NER = typed entities.
  • Both are sequence labeling — context of neighbors matters (CRF/BiLSTM).
  • NER powers search, KG population, redaction, analytics.
🎤Interview Q&A
Why model tag sequences, not tokens independently?
Tags are correlated: DET→NOUN, I-PER can't follow O. A CRF/sequence model enforces valid transitions, beating per-token classifiers.
What are BIO/IOB tags?
B- begins an entity, I- continues, O outside. 'New York City' → B-GPE I-GPE I-GPE, so multi-token spans are recoverable.
How to evaluate NER?
Entity-level P/R/F1 with exact span+type match. Token accuracy misleads because O dominates.
08

Classification, Pipelines & Evaluation

Intermediate▶
🔍Intuition

Show a model many (text, label) pairs; it learns which words push toward which label, then labels new text. The hard part isn't training — it's measuring honestly on unseen data.

📐Math
LogReg: p(y=k|x) = softmax(wk·x + bk), fit by cross-entropy + λ‖W‖2.
precision = TPTP+FP   recall = TPTP+FN   F1 = 2PRP+R
🧩Concept

Wrap vectorizer + model in a Pipeline so the same transform hits train and test → no leakage. Use macro-F1 under imbalance.

💻Code demo
from sklearn.pipeline import Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

pipe = Pipeline([("tf", TfidfVectorizer(ngram_range=(1,2))),
                 ("clf", LogisticRegression(max_iter=1000, class_weight="balanced"))])
pipe.fit(X_train, y_train)                        # vectorizer fit on TRAIN only
print(classification_report(y_test, pipe.predict(X_test)))
✅Key takeaways
  • Pipelines prevent data leakage; fit the vectorizer on train only.
  • Under imbalance report precision/recall/F1 + confusion matrix, not accuracy.
  • Linear models over TF-IDF are strong and interpretable.
🎤Interview Q&A
Precision vs recall — an airline example?
Flagging negative tweets: high precision = few false alarms (agents not wasting time); high recall = few missed complaints. Tune the threshold to the cost of a miss vs a false alarm.
What is data leakage and how do pipelines prevent it?
Leakage = test/future info influencing training (e.g. fitting the vectorizer on all data). A Pipeline fits each step on the training fold only during CV, so vocabulary/IDF come solely from train.
Why macro-F1 for imbalance?
It averages per-class F1 equally, so a tiny class counts as much as the dominant one; accuracy lets the majority hide poor minority performance.
Why does Naive Bayes work despite its 'naive' assumption?
Conditional independence of words is false, but the resulting boundary is often well-placed, and it's fast and robust on sparse high-dim text.
09

Topic Modeling (LDA)

Advanced · unsupervised▶
🔍Intuition

No labels. LDA reads many documents and discovers recurring topics (word clusters), describing each doc as a mixture: 70% delays, 30% staff.

📐Math
Generative story: θd ~ Dir(α) (doc-topic mix); z ~ Cat(θd) (per-word topic); w ~ Cat(βz) (word). Inference recovers θ and β that best explain the corpus.
🧩Concept

You pick the number of topics; you interpret them from their top words.

💻Code demo
from sklearn.decomposition import LatentDirichletAllocation
from sklearn.feature_extraction.text import CountVectorizer
corpus = ["flight delayed lost luggage","cancelled flight rude crew",
          "hotel clean great view breakfast","friendly hotel staff comfortable bed"]
dtm = CountVectorizer(stop_words="english").fit_transform(corpus)
lda = LatentDirichletAllocation(n_components=2, random_state=0).fit(dtm)
# inspect lda.components_ -> topic 0 ≈ {flight, delayed, crew}; topic 1 ≈ {hotel, breakfast}
✅Key takeaways
  • Docs are mixtures of topics; topics are distributions over words.
  • Choose #topics; interpret via top words; evaluate with coherence.
  • Great for exploration, tagging, dashboards.
🎤Interview Q&A
How to choose the number of topics?
Sweep k; pick by topic coherence (c_v), held-out perplexity, and human interpretability — coherence usually beats perplexity for readability.
LDA vs LSA vs NMF?
LSA/SVD: signed, hard to read. NMF: non-negative, parts-based, crisp on short text. LDA: probabilistic, per-doc topic distributions, most interpretable.
10

RNN — Recurrent Neural Networks

Advanced▶
🔍Intuition

BoW forgets order, but “the movie was not good” needs it. An RNN reads tokens one at a time, keeping a running memory (hidden state h) — like updating your understanding word by word.

📐Math
ht = tanh(Wxh·xt + Whh·ht-1 + b)    yt = Why·ht
The same weights are reused at every step (weight sharing across time).
🧩Concept

Great for order-sensitive tasks. Weakness: vanishing gradients over long sequences — early tokens stop influencing learning.

💻Code demo
import numpy as np
def rnn_forward(xs, Wxh, Whh, Why, bh, by):
    h = np.zeros(Whh.shape[0]); outs = []
    for x in xs:                               # read one token at a time
        h = np.tanh(Wxh@x + Whh@h + bh)        # update memory
        outs.append(Why@h + by)                # emit output
    return np.array(outs), h
# feed a one-hot token sequence -> final hidden state summarizes the whole input
✅Key takeaways
  • RNNs carry a hidden state across time → they model order.
  • Weights are shared across time steps.
  • Vanishing gradients limit long-range memory.
🎤Interview Q&A
Why do vanilla RNNs vanish/explode gradients?
Backprop-through-time multiplies many Jacobians; repeated multiplication by weights with singular values <1 shrinks gradients to zero, >1 blows them up — so early tokens get no signal.
What is weight sharing across time?
The same W matrices are applied at every step, so the model generalizes across positions and handles variable-length input with a fixed parameter count.
RNN vs feed-forward for text?
RNNs consume sequences and keep memory, capturing order and variable length; feed-forward nets need a fixed-size input (e.g. averaged embeddings) and lose order.
11

LSTM & GRU — gated memory

Advanced▶
🔍Intuition

LSTMs add gates that decide what to keep, add, and expose from a long-term memory cell — so information can survive across many steps, fixing the RNN's forgetting.

📐Math
it=σ(Wi[h,x])   ft=σ(Wf[h,x])   ot=σ(Wo[h,x])   gt=tanh(Wg[h,x])
ct = ft⊙ct-1 + it⊙gt    ht = ot⊙tanh(ct)
The additive ct path is the 'constant error carousel' that lets gradients flow far.
🧩Concept

Use for order-sensitive NLP. Pattern: tokens → Embedding → (Bi)LSTM → Dense. BiLSTM reads both directions; GRU merges gates for fewer parameters.

💻Code demo
import numpy as np
def sigmoid(z): return 1/(1+np.exp(-z))
def lstm_step(x, h, c, W, b):
    z = W@np.concatenate([h,x]) + b; H = h.shape[0]
    i, f, o = sigmoid(z[:H]), sigmoid(z[H:2*H]), sigmoid(z[2*H:3*H])
    g = np.tanh(z[3*H:])
    c = f*c + i*g          # forget * old memory  +  input * new candidate
    h = o*np.tanh(c)       # output gate exposes part of the memory
    return h, c
# f≈1 keeps memory across many steps -> solves vanishing gradients
✅Key takeaways
  • Gates (i, f, o) control memory; the cell state c is additive.
  • That additive path solves vanishing gradients over long spans.
  • BiLSTM = both directions; GRU = lighter, often as good.
🎤Interview Q&A
How exactly does the cell state solve vanishing gradients?
c updates additively (c_t = f·c_{t-1} + i·g) with a gate near 1, giving a near-constant-error path so gradients flow across long spans with little decay.
LSTM vs GRU vs Transformer — when each?
GRU: fewer params, fast, great on small data. LSTM: slightly more expressive. Transformer: parallel, best long-range + big data, but data/compute hungry. Short text + small data → TF-IDF+linear or small BiLSTM often wins.
What is a BiLSTM and when does it help?
Two LSTMs (left→right and right→left) concatenated, giving each token past and future context — great for tagging/classification, not for streaming generation.
What is temperature in LSTM/LLM text generation?
A softmax scaling on the next-token logits: low = safe/repetitive, high = diverse/risky. It trades coherence for creativity.

Project 03 · sequence generation

✍️ Tweet / Headline Generator

Generate airline-style tweets. Generation is next-token prediction — the essence of RNN/LSTM and of GPT. Start with a transparent n-gram baseline, then an LSTM language model.

Data: any tweet/headline corpusself-supervisedgenerativemetric: perplexity / human
🧭Pipeline
  • Trigram Markov baseline: fully transparent, runs instantly
  • Build growing-prefix training pairs (predict the next token)
  • Embedding → LSTM → softmax over the vocabulary
  • Sample with a temperature knob (creativity dial)
💻Classical baseline
from collections import defaultdict
class Markov:
    def __init__(s, n=2): s.n=n; s.d=defaultdict(list)
    def fit(s, texts):
        for t in texts:
            toks = ["<s>"]*s.n + t.split() + ["</s>"]
            for i in range(len(toks)-s.n): s.d[tuple(toks[i:i+s.n])].append(toks[i+s.n])
        return s
    def generate(s, maxlen=16):
        import numpy as np; ctx=("<s>",)*s.n; out=[]
        for _ in range(maxlen):
            nxt=s.d.get(ctx);  w = np.random.choice(nxt) if nxt else "</s>"
            if w=="</s>": break
            out.append(w); ctx=tuple((list(ctx)+[w])[-s.n:])
        return " ".join(out)
Markov(2).fit(train_texts).generate()
🔁 Extend to RNN/LSTM
tokens → Embedding(64) → LSTM(128) → Dense → softmax(|V|) · sample with temperature
tok = Tokenizer(); tok.fit_on_texts(train); V = len(tok.word_index)+1
seqs = []
for line in train:
    ids = tok.texts_to_sequences([line])[0]
    for i in range(1, len(ids)): seqs.append(ids[:i+1])      # growing prefixes
seqs = pad_sequences(seqs); Xg, yg = seqs[:,:-1], seqs[:,-1]

model = Sequential([layers.Embedding(V,64), layers.LSTM(128), layers.Dense(V, activation="softmax")])
model.compile(loss="sparse_categorical_crossentropy", optimizer="adam")
model.fit(Xg, yg, epochs=30, batch_size=128)

def generate(seed, n=10, temperature=1.0):
    for _ in range(n):
        ids = pad_sequences(tok.texts_to_sequences([seed]), maxlen=Xg.shape[1])
        logits = np.log(model.predict(ids, verbose=0)[0]+1e-9)/temperature
        p = np.exp(logits)/np.exp(logits).sum()
        seed += " " + tok.index_word.get(np.random.choice(len(p), p=p), "")
    return seed
